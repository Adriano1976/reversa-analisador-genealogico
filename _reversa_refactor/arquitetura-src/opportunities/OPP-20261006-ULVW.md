## Antes observado

O ciclo é direto e verificável por varredura de `src/`:

```text
core/path_search.py:51        from reporting.mermaid_render import (...)
core/dna_analysis.py:51       from reporting.mermaid_render import generate_mermaid_graph
reporting/mermaid_render.py:16  from core.family_navigation import ...   (4 nomes)
reporting/mermaid_render.py:22  from core.path_finding import find_ancestral_path
reporting/mermaid_render.py:23  from core.gedcom_state import get_name, people
```

A intenção declarada da reorganização (ADR-11) era `parsers/` → `core/` → `reporting/`. O grafo
real não é esse.

A causa não é o `import`: é o que o renderizador **faz** com o domínio. `generate_mermaid_graph`
chama `get_spouses(common_ancestor_id)` em `mermaid_render.py:78` para decidir se o topo do
diagrama é um casal ou uma pessoa, e `generate_mermaid_graph_indirect_bridge` chama
`find_ancestral_path` (`:135`, `:231`), `pick_spouse_for_couple` (`:139`, `:235`),
`split_path_by_marriage` (`:126`) e `exclude_tail` (`:213`, `:246`). São decisões sobre o
parentesco tomadas dentro do módulo de apresentação.

## Transformação proposta

Inverter a dependência movendo a decisão para o núcleo e deixando o render consumir um valor:

1. o núcleo monta uma estrutura de diagrama (nós, colunas, casais e arestas) a partir do caminho
   e do dossiê;
2. `reporting/mermaid_render.py` passa a receber essa estrutura e só serializa texto, sem
   importar `core/` em momento algum;
3. `reporting/` vira pacote folha, ao lado de `utils/`.

A prova de preservação já existe no repositório: `tests/test_characterization_mermaid.py` e
`tests/test_mermaid_escape.py` comparam a string Mermaid gerada, e o contrato de escape do
rótulo é lista branca fechada (`_LABEL_SEGURO`). Manter a string byte a byte é o critério de
aceite.

## Risco

O módulo tem o maior histórico de defeitos do sistema (BUG-20260929-J6PQ e BUG-20261002-T4ZM) e
a primeira correção do escape precisou ser refeita. A transformação é comportamentalmente
neutra mas mexe no ponto mais sensível do projeto: a string gerada. Exige os dois arquivos de
caracterização verdes antes e depois, mais comparação por AST das funções movidas.

## Aplicada em 2026-10-06

Registro completo em `transformations/OPP-20261006-ULVW-ciclo-core-reporting/transformation.md`.

A costura aplicada foi **injeção do resolvedor de domínio**, e não movimentação do layout. A rota
mais limpa (mover o layout para o núcleo, deixando `reporting/` como serializador folha) foi
**recusada**: `_reversa_sdd/architecture.md` §3 afirma que `reporting/` "não é folha, e não pode
ser", porque as decisões de layout são decisão de negócio. O verbo `decouple` não autoriza
redistribuir responsabilidade.
