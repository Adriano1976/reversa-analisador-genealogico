2. A restrição que define a costura

A rota óbvia está proibida pelo próprio projeto.

A saída natural seria mover o layout para o núcleo: se o core montasse a estrutura do diagrama e entregasse pronta, o renderizador viraria um serializador burro sem nenhum import de core, e o ciclo morreria.

_reversa_sdd/architecture.md:73 recusa exatamente isso, com todas as letras: "reporting/ não é folha, e não pode ser", porque as decisões de layout são decisão de negócio (o casal do ancestral comum, a escolha de qual ancestral ancora o ramo, o ponto de corte por casamento). ADR-11 mantém essas regras em reporting/ de propósito. O escopo do verbo decouple proíbe redistribuir responsabilidade, e a oportunidade registra isso como premissa.

3. A costura proposta: inversão sem mover lógica

O ciclo existe porque o renderizador busca os dados de que precisa. A costura inverte a direção da dependência de código sem mudar de lugar a decisão: o chamador passa um resolvedor de domínio como argumento, e reporting/ deixa de importar core/ por completo.

Antes

reporting/mermaid_render.py
  from core.family_navigation import (...)
  from core.path_finding import find_ancestral_path
  from core.gedcom_state import get_name, people
        │
        │ import direto: ciclo
        ▼
core/path_search.py
  from reporting.mermaid_render import (...)

Depois

reporting/mermaid_render.py
  # nenhum import de core
  def generate_mermaid_graph(
      path, p1_id, p2_id, common_ancestor_id, dominio): ...
        ▲
        │ injetado como parâmetro
        │
core/path_search.py
  from reporting.mermaid_render import (...)
  from .diagram_domain import resolvedor_de_diagrama
  ...
  generate_mermaid_graph(..., resolvedor_de_diagrama())

O resolvedor é uma única costura explícita: um mapeamento nomeado das cinco consultas de domínio que o desenho precisa. Ele fica no core, onde essas funções já vivem, e não acrescenta lógica: só dá nome ao contrato que hoje está implícito nos imports. 

src/core/diagram_domain.py   (novo, cerca de 25 linhas)

def resolvedor_de_diagrama() -> dict:
    """As consultas de dominio que o desenho do diagrama precisa."""
    from .family_navigation import (
        exclude_tail, get_spouses, pick_spouse_for_couple, split_path_by_marriage,
    )
    from .path_finding import find_ancestral_path
    from .gedcom_state import get_name, people
    return {
        "get_name": get_name, "people": people,
        "get_spouses": get_spouses, "split_path_by_marriage": split_path_by_marriage,
        "pick_spouse_for_couple": pick_spouse_for_couple, "exclude_tail": exclude_tail,
        "find_ancestral_path": find_ancestral_path,
    }

Nota de forma: o resolvedor é um dict, e não uma classe ou Protocol, para respeitar paradigm_decision.md, que manda o núcleo permanecer em funções puras e não introduzir objetos com estado nos cálculos.

6. Risco e reversão

  • Risco declarado: o renderizador é o componente com mais defeitos registrados (2 de 5) e o único cuja correção precisou ser refeita. Por isso a transformação não toca _LABEL_SEGURO, _mermaid_label nem _mermaid_sid.
  • Vermelho, reverte: qualquer falha nos 39 testes de caracterização, ou a string Mermaid divergindo em um caractere, e o diff é revertido integralmente.
  • Reversível por: CHG-NNN.diff guardado na pasta da transformação.
  • Gate de edição do legado: liberado. allowLegacyEdits: true com allowedPaths cobrindo src/**.

7. O que esta transformação não faz

  • Não resolve a inversão de camada em si: o reporting/ continua contendo decisão de negócio de apresentação, como architecture.md:73 exige que continue. O ciclo acionável por importação morre; a decisão de fronteira segue registrada como 🔴 no soul.md §3 D2.
  • Não mexe em parsers/ (é a OPP-20261006-LIGH).
  • Não reduz o __all__ de path_search (é a OPP-20261006-ESKO), preservando test_mermaid_escape.py intacto.
  • Não toca o estado global (é a OPP-20261006-3WR5).

Aprovação pedida: aplicar o change set descrito na seção 3, com a rede de segurança da seção 1 verde antes e depois. Nenhum arquivo será tocado antes desta aprovação.
